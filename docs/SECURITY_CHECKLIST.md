# Проверка безопасности перед передачей клиенту

Этот список дополняет автоматический `npm run launch-check`. Он не подтверждает юридическое соответствие и не заменяет аудит инфраструктуры.

## Секреты и доступы

- [ ] Все значения, когда-либо находившиеся в удалённом `.env.txt`, отозваны и перевыпущены.
- [ ] `.env`, `.env.*`, client-конфигурации и backup-файлы отсутствуют в Git.
- [ ] Для PII, phone lookup, session, CSRF и MFA используются разные случайные ключи.
- [ ] Production-ключи не применяются в development/demo.
- [ ] В GitHub включены secret scanning и push protection.
- [ ] Первый ADMIN использует уникальный пароль и завершённый TOTP enrollment; recovery-коды сохранены офлайн.
- [ ] Ненужные администраторы и активные сессии отозваны.

## Сеть и HTTP

- [ ] PostgreSQL доступен только во внутренней Docker-сети.
- [ ] Наружу опубликованы только 80/443 reverse proxy.
- [ ] DNS и автоматический TLS проверены; HSTS включается только после успешного HTTPS-запуска.
- [ ] Reverse proxy перезаписывает, а не доверяет входящим `X-Forwarded-For`/`X-Real-IP`.
- [ ] `ALLOWED_STOREFRONT_ORIGINS` содержит только точные HTTPS origins без wildcard.
- [ ] CSP работает без `unsafe-eval`; admin нельзя встраивать во frame.
- [ ] Body limits, Origin/CSRF checks и rate limits проверены реальными запросами.

## Персональные данные

- [ ] Platform и PostgreSQL находятся в согласованном российском контуре; Vercel storefront не принимает и не проксирует checkout PII.
- [ ] Телефон, email, адрес, детали доставки, комментарий и IP хранятся только в AES-256-GCM envelopes.
- [ ] Plaintext PII отсутствует в URL, localStorage, логах, audit metadata, telemetry и Метрике.
- [ ] Retention-периоды утверждены, retention job включён и удаление проверено на тестовых данных.
- [ ] Процедуры ротации ключа и lazy re-encryption проверены по runbook.

## Платежи и заказы

- [ ] CARD/SBP routing настроен оператором; попытка платежа навсегда связана с исходным провайдером.
- [ ] ЮKassa/T-Bank credentials выданы для нужного магазина и не являются demo-значениями.
- [ ] Sandbox smoke tests CARD, SBP и полного возврата выполнены отдельно для каждого активного провайдера.
- [ ] Webhook URL доступны только по HTTPS; replay, amount/currency/order mismatch отклоняются.
- [ ] Redirect покупателя не считается подтверждением оплаты.
- [ ] Reconciliation, outbox и refund workers работают независимо от пользовательского трафика.
- [ ] Отмена оплаченного заказа создаёт асинхронный полный возврат и audit event.

## Каталог, файлы и фискализация

- [ ] Все цены, позиции без цены, составы и веса подтверждены оператором.
- [ ] Для каждого заказываемого товара заполнены подтверждённые fiscal VAT/subject/mode/measure.
- [ ] СНО и fiscal delivery attributes подтверждены бухгалтером/оператором.
- [ ] Загрузки принимают только JPEG/PNG/WebP/AVIF с допустимой сигнатурой и размером.
- [ ] Local media и база находятся на постоянных volumes и включены в проверяемую backup-процедуру.

## Legal и организационные действия

- [ ] Юрист определил `CONTRACT`/`CONSENT` по каждой операции обработки ПД.
- [ ] Версии legal-документов утверждены, их SHA-256 совпадают с файлами и БД.
- [ ] Уведомление РКН, локальные акты, ответственный и договоры с обработчиками подтверждены вне кода.
- [ ] Реквизиты, часы, зоны, стоимость доставки, минимальная сумма и контакты реальны.
- [ ] Cookie banner проверен: до opt-in нет запросов к `mc.yandex.ru`, noscript beacon и Webvisor.

## Резервирование и восстановление

- [ ] Утверждены RPO/RTO, включён ежедневный сжатый `pg_dump`, хранится минимум семь копий.
- [ ] Restore drill выполнен в отдельную тестовую БД и зафиксирован датой/результатом.
- [ ] Backup legal-файлов и их hashes выполняется вместе с release-артефактами.
- [ ] Обновления БД используют expand–migrate–contract; destructive migration имеет отдельный план и backup.
