# Создание нового клиента

Один экземпляр приложения обслуживает одно заведение. Команда не создаёт мультитенантный SaaS и по умолчанию отказывается перезаписывать существующий профиль или ADMIN.

## Перед началом

1. Создайте отдельную пустую PostgreSQL для клиента.
2. Скопируйте `.env.example` в локальный `.env` и задайте только реальные значения.
3. Выполните `npm ci`, `npm run prisma:generate` и `npm run db:migrate:deploy`.
4. Подготовьте CSV или JSON по шаблону из `examples/`.
5. Задайте `MFA_ENCRYPTION_KEY`: base64-представление 32 случайных байт.

## Интерактивный режим

```bash
npm run create-client
```

Пароль вводится без отображения в терминале, хешируется Argon2id и не записывается в файлы. После создания URI TOTP и recovery-коды выводятся один раз. Сохраните их офлайн и не добавляйте в Git.

## Режим конфигурации

Скопируйте `clients/example.client.json`, измените публичные данные и оставьте только имя переменной с паролем:

```bash
export CLIENT_ADMIN_PASSWORD='длинный-уникальный-пароль'
npm run create-client -- --config ./clients/my.client.json
unset CLIENT_ADMIN_PASSWORD
```

Реальный пароль нельзя помещать в JSON. Файлы `clients/*.client.json`, кроме примера, игнорируются Git.

## Что команда намеренно не придумывает

- юридические реквизиты, налоговый режим и VAT-коды;
- часы работы и зоны доставки;
- ключи ЮKassa/T‑Bank;
- юридическое одобрение документов.

Передача адреса клиента включает самовывоз с подписью на основе этого адреса. Доставка остаётся выключенной до создания конкретной зоны. Введённая стоимость доставки сохраняется как ожидающее подтверждения значение, а не как активное правило.

`--force` разрешает осознанно обновить профиль и перевыпустить MFA для ADMIN с тем же email. Все его сессии отзываются. Используйте флаг только после резервной копии.
