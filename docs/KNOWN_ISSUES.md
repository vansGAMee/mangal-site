# Реестр известных особенностей и ограничений (KNOWN_ISSUES)

В данном документе зафиксированы технические решения, допущения и известные ограничения текущей версии продукта.

---

## 1. Архитектурные особенности

1. **Модель Single-Tenant**:
   - Приложение спроектировано как **одна изолированная установка для одного заведения**;
   - Архитектура не содержит мультитенентного SaaS-слота (нельзя обслуживать сотни разных кафе из одного инстанса БД). Для каждого клиента разворачивается отдельный VPS.

2. **Загрузка и хранение медиа-файлов**:
   - По умолчанию используется локальный драйвер хранения `STORAGE_DRIVER=local` в директории `/app/uploads`, смонтированной через volume;
   - При масштабировании на несколько экземпляров контейнеров рекомендуется использовать совместимое S3-хранилище.

3. **Секреты и безопасности**:
   - Переменные окружения и ключи шифрования персональных данных генерируются случайным образом и хранятся в файлы `.env`, которые исключены из Git;
   - Сброс администратора через `admin:create` при имеющихся админах в базе требует явного флага `--force`.

---

## 2. Развёртывание на Vercel (Vercel Integration)

1. **Канонический контур приложения**:
   - Канонический рабочий контур заказа и админки работает на **VPS в Docker**;
   - Размещение Storefront на Vercel отдельно возможно, но требует настройки CORS и внешнего HTTPS API адреса для Platform API (на VPS). Размещение базы данных и бэкенда на Vercel не является целевым сценарием.
